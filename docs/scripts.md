# Workspace Script Catalogue

Use these scripts from the `fasthep-dev` repository root. Do not run mutating,
release, submission, or external-write scripts merely to inspect them.

| Script | Purpose | Typical invocation | Environment | External services or credentials | Effect |
|---|---|---|---|---|---|
| `scripts/dev/git-status-summary.py` | Summarise dirty state and upstream sync for local submodule checkouts. | `pixi run --environment scripts git-status` or `python scripts/dev/git-status-summary.py` | `scripts` Pixi env or system Python with Git available | Git remotes only if upstream comparison needs configured remotes; no credentials for local status | Read-only |
| `scripts/dev/repo_index.py` | Generate compact package, symbol, profile, command, test, and registry indexes. | `pixi run --environment scripts repo-index` or `python scripts/dev/repo_index.py --out .ai` | `scripts` Pixi env; optional PyYAML improves YAML parsing | None | Mutating: writes index files, default `.ai/` |
| `scripts/dev/clean_build.py` | List `build/` run directories below the workspace (FAST-HEP only, `hinv/` is skipped) and, on request, delete selected ones. Protects folders that contain, or sit below, a `clean.keep` file, and folders with git-tracked files. | List: `pixi run --environment scripts clean-build`; delete: `pixi run --environment scripts clean-build-execute --older-than 14` (or `--all`, `--only GLOB`, `--whole`) | `scripts` Pixi env or system Python with Git | None | Read-only by default; destructive with `--execute`: needs a selection and a typed confirmation on a terminal, refuses without one, no option to skip (human gate) |
| `scripts/dev/push_branches.py` | Show, and on request push, the FAST-HEP branches of a stacked PR set listed in `tasks/push-manifest.yaml`; never forces, skips diverged branches. | Dry run: `pixi run --environment scripts push-branches`; push: `pixi run --environment scripts push-branches-execute` | `scripts` Pixi env or system Python with Git and PyYAML | Git remotes (SSH keys); `ls-remote` in the dry run | Read-only external query by default; external-write with `--execute`: typed confirmation on a terminal, refuses without one, no option to skip (human gate) |
| `scripts/dev/sync_dependabot.py` | Keep every package's `.github/dependabot.yml` equal to `dot-github/templates/dependabot.yml` (Dependabot has no inheritance, so each repository carries a copy). Packages are those in `releases.json`. Shows each file as same, different (with the diff) or missing. | Dry run: `pixi run --environment scripts sync-dependabot-dry`; write: `sync-dependabot` | `scripts` Pixi env or system Python with Git, the `dot-github` submodule | None | Read-only by default; `--write` changes files in the package working trees only (no commit, no push) and refuses a file with uncommitted changes |
| `scripts/dev/peakrss.py` | Run any command and print `=== PEAK_RSS_MB <n> WALL_S <n>`: the peak resident memory of the largest descendant process (`RUSAGE_CHILDREN`) and the wall time; exits with the command's exit code. A cross-check for the `hep.resource_usage` hook of `fasthep-curator` (partition task only); to be compared with `curator/src/fasthep_curator/hooks/resource_usage.py` later, then merged or kept as a separate hook. | `python scripts/dev/peakrss.py COMMAND [ARGS...]`, for example under a cap: `systemd-run --user --scope -p MemoryMax=12G -p MemorySwapMax=0 python scripts/dev/peakrss.py fasthep run ...` | System Python (stdlib only) | None | Read-only (runs the given command, which has its own effects) |
| `scripts/dev/tasks_sync.py` | Mirror open issues of the FAST-HEP roadmap project (GitHub) into `tasks/issues/`. | `pixi run --environment scripts tasks-sync` (dry run: `tasks-sync-dry`) | `scripts` Pixi env or system Python | `GITHUB_TOKEN` from the environment or from the env file given with `--env-file` or `FASTHEP_ENV_FILE` (location differs per machine; read only, never printed) | Read-only towards GitHub; writes local files below `tasks/issues/` (only files it generated); `--prune` deletes stale generated files and is a human gate |
| `scripts/helpers/condor_info.py` | Print basic HTCondor collector and scheduler information. | `python scripts/helpers/condor_info.py` | Python with `htcondor2` installed and HTCondor client configured | HTCondor collector/schedd access; site configuration may require credentials | Read-only external query |
| `scripts/release/check_release.py` | Check release readiness from `releases.json`: clean repos, branches, package metadata, and existing tags. | `pixi run --environment scripts release-check` or `python scripts/release/check_release.py releases.json` | `scripts` Pixi env or Python with stdlib TOML support | Git remotes for remote tag checks; network/auth may be needed for private remotes | Read-only but can contact remotes |
| `scripts/release/print_release_plan.py` | Print release order, versions, distributions, tags, and manual hard stops. | `pixi run --environment scripts release-plan` or `python scripts/release/print_release_plan.py releases.json` | `scripts` Pixi env or system Python | None | Read-only |
| `scripts/release/update_versions.py` | Update package versions and FAST-HEP dependency pins from `releases.json`. `workshop` and `fasthep` (`release_data.PINNED_LAST`) are only updated via `--package`, and a non-dry-run refuses (`release_data.validate_pin_readiness`) if any FAST-HEP dependency it would pin isn't tagged yet. `workshop/pyproject.toml`'s pins are written as `>=` (floor), permanently, since that file also serves as editable dev-workspace package metadata; `fasthep/pyproject.toml`'s and `workshop/pixi.toml`'s pins stay exact (`==`). | Default batch (all packages except `workshop`/`fasthep`) dry run: `pixi run --environment scripts release-update-versions-dry`; write: `pixi run --environment scripts release-update-versions`. `workshop` only: `release-update-versions-workshop-dry` / `release-update-versions-workshop`. `fasthep` only: `release-update-versions-fasthep-dry` / `release-update-versions-fasthep` | `scripts` Pixi env; needs `packaging` | None | Mutating unless `--dry-run` |
| `scripts/release/aggregate_changelog.py` | Aggregate the per-package changelogs into a new `## [<release version>]` block in `fasthep/CHANGELOG.md`, inserted under `## [Unreleased]`. Each package contributes its `## [<its version in releases.json>]` section (categories nest one level down); a package left at an older version is listed as `Unchanged: stays at <version>`. Refuses (non-zero exit) if a package that is part of the release has no section for that version: split `[Unreleased]` first. | Dry run: `pixi run --environment scripts release-aggregate-changelog-dry`; write: `release-aggregate-changelog` | `scripts` Pixi env or system Python | None | Dry run read-only; the write mutates `fasthep/CHANGELOG.md` |
| `scripts/release/tag_packages.py` | Create and optionally push annotated release tags in package repositories. First checks the changelog contract for every package about to be tagged (dated, non-empty `## [X]`, empty `## [Unreleased]`, via the shared tool) and refuses the whole batch, also in a dry run, if one fails. A batch run with no `--package` always excludes `workshop` and `fasthep` (`release_data.PINNED_LAST`); tag each individually, after its pins are updated, once everything it depends on is already tagged. A package whose tag already exists is skipped with a note, not an error (a package with no changes since its last tag stays at that version in `releases.json`, and a re-run resumes after a partial failure). After creating a tag (not on `--dry-run`), touches the package's `pyproject.toml` so `pixi`/`uv` stop resolving its pre-tag dev-snapshot version (they cache an editable package's hatch-vcs version by its `pyproject.toml` mtime, not by git state). | Default batch dry run: `pixi run --environment scripts release-tag-dry`; create local tags: `release-tag`; push: `release-tag-push`. `workshop` only: `release-tag-workshop-dry` / `release-tag-workshop` / `release-tag-workshop-push`. `fasthep` only: `release-tag-fasthep-dry` / `release-tag-fasthep` / `release-tag-fasthep-push` | `scripts` Pixi env or system Python with Git | Git remotes and push credentials when `--push` is used | Mutating; potentially external-write with `--push` |
| `scripts/release/validate_release.sh` | Step 7 of the release procedure: run `workshop`'s examples (CMS/Zmumu, CMS/L1Trigger, LZ/mssi) and tutorials 01 to 06 in workshop's own released pixi environment, one run at a time, outputs in `workshop/build/<version>-*` and a log and `summary.txt` in `workshop/build/<version>-validation/`. Defaults to the latest workshop tag; `--version` overrides, `--skip <tutorial>` adds skips (`01-read-data/03-remote-data` is always skipped). Dry run unless `--run`; with `--run` it stops before running if the input data is missing (the developer populates it from the `remote_data.json` manifests). Exits non-zero if any run failed. | `pixi run --environment scripts release-validate-dry` (list); `release-validate` (run) | `bash`, Git, `pixi` (workshop's own environment) | Data files under `workshop/data` | Dry run read-only; `--run` writes only under `workshop/build/` |
| `scripts/release/release_changelog.py` | Changelog step of the release. `write`: for each package whose `releases.json` version is not tagged yet, draft `## [X]` with git-cliff (rules and template from the `FAST-HEP/.github` checkout, `dot-github`) and insert it under the empty `## [Unreleased]`; refuses if a package has no visible commit; with `--write` also commits each file locally (`docs(changelog): add X release`), and nothing is written unless every package drafts. `check`: the changelog contract for every package, and that `fasthep`'s block equals the aggregate. Details: `docs/release-path.md`. | Dry run (the preview): `pixi run --environment scripts release-changelog-dry`; write and commit: `release-changelog`; contract: `release-check-changelog` | `scripts` Pixi env (`git-cliff`), checkout of `FAST-HEP/.github` | None | Dry run and `check` read-only; `write` mutates package changelogs and makes local commits |
| `scripts/release/changelog_tools.py` | Helper that calls the shared changelog tool in the `FAST-HEP/.github` checkout (`FASTHEP_DOTGITHUB` overrides the path); imported by the release scripts, not run directly. | none | `scripts` Pixi env | None | Read-only |
| `scripts/release/backfill_releases.py` | Create the GitHub Releases that tags made before the release job never got: notes are the package's own `## [X]` section plus the PyPI link; tags without a section are listed and skipped; newest tag is latest. `--since` (default 2026.10.0), `--package`. | Dry run: `pixi run --environment scripts release-notes-backfill-dry`; publish: `release-notes-backfill-execute` | `scripts` Pixi env (`gh`), checkout of `FAST-HEP/.github` | `gh` login or `GH_TOKEN` from the token file named for the session (never read or printed by the script) | Read-only (`gh release list`) by default; external-write with `--execute`: typed confirmation on a terminal, refuses without one, no option to skip (human gate) |
| `scripts/release/tests/test_tag_packages.py` | Unit tests for release tag naming/message helpers. | `pixi run --environment dev python -m pytest scripts/release/tests/test_tag_packages.py` | `dev` Pixi env or Python with pytest | None | Read-only test |
| `scripts/release/tests/test_update_versions.py` | Unit tests for dependency pin rewriting and dry-run behaviour. | `pixi run --environment dev python -m pytest scripts/release/tests/test_update_versions.py` | `dev` Pixi env or Python with pytest and `packaging` | None | Read-only test using temporary files |
| `scripts/release/tests/test_validate_release.py` | Tests for `validate_release.sh` with a fake `pixi`: dry run, section range and remote skip, failing run exit code, missing-data stop. | `pixi run --environment dev python -m pytest scripts/release/tests/test_validate_release.py` | `dev` Pixi env or Python with pytest and bash | None | Read-only test using temporary files |

Notes:

- `pixi.toml` exposes release helpers as tasks in the `scripts` environment.
- `clean` removes `__pycache__`, caches and `dist/` only; `build/` folders are handled by
  `clean-build` (they are gitignored and can hold the only copy of validation outputs).
- `pixi run` can fail on the AFS lock on lxplus; the scripts also run directly with the
  environment's Python, for example `hinv/.pixi/envs/dev/bin/python scripts/dev/clean_build.py`.
- `release-tag-push` writes to Git remotes; use only when explicitly requested.
- Destructive or external-write actions (`clean-build-execute`, `push-branches-execute`, `release-notes-backfill-execute`, `--prune`) are
  human gates: a typed confirmation on a terminal, refused without one, no flag to skip it. Agents do
  not run them.
- `hinv/` (CMS analysis integration) is not FAST-HEP: its tooling lives in `hinv/chip` and the
  workspace scripts and pixi tasks do not touch it.
- `scripts/helpers/condor_info.py` is intentionally live-site dependent and
  should not be part of routine local documentation checks.
